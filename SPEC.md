# PRIDE Poker Club — спецификация

Telegram-бот с веб-приложением (Telegram Web App) для покерного клуба PRIDE: рейтинги игроков по месяцам, личная статистика, история турниров, легенды клуба.

## Архитектура

```
index.js            — точка входа: импортирует server.js и bot.js
server.js           — Express API + раздача статики из public/
bot.js              — Telegram-бот (/start, /help, кнопка открытия Web App)
public/
  index.html        — одностраничное приложение (вкладки + экраны)
  app.js            — вся логика фронтенда (vanilla JS)
  style.css         — стили
snapshot.mjs        — инструмент регрессионного тестирования API
```

**Стек:** Node.js (ES modules), Express, node-telegram-bot-api, Supabase (PostgreSQL), Google Sheets API, Chart.js (графики), PostHog (продуктовая аналитика), Rollbar (ошибки).

## Источники данных

### 1. Старая таблица — рейтинги (`OLD_SPREADSHEET_ID`)

`1t92y6HNg9RPPBENU6ydda8KqJoCSVRDEIZmDwjk0Jn0` — **публичная**, читается через CSV-export без авторизации.

Один лист = один месяц. Все листы перечислены в `SHEETS` (ключ месяца → gid), диапазон: апрель 2025 — июнь 2026.

Структура листа (строка 2 = заголовок):
| ... | Игрок | 1 мая | 2 мая | ... | Итого |
|-----|-------|-------|-------|-----|-------|

- Колонки определяются динамически (`detectSheetStructure`): ищутся заголовки «Игрок» и «Итого», всё между ними — даты игр (фоллбэк: индексы 3 и 22).
- Данные игроков начинаются со строки 3 (`lines.slice(2)`).
- Очки за игру — целые числа; пустая ячейка = не играл.

### 2. Новая таблица — итоги турниров (`NEW_SPREADSHEET_ID`)

`1LMiGLPmt2GQduqCg4SpWv5-9jUHKb5BIVw2PM5OjG7w` — **приватная**, читается через Google Sheets API сервисным аккаунтом (env `GOOGLE_SERVICE_ACCOUNT_B64`).

Колонки (первая строка — заголовок):
| A: дата (ДД.ММ.ГГГГ) | B: название турнира | C: победитель |

Из неё строятся две мапы (`loadNewTableMaps`, один проход, общий кэш):
- `winners`: дата → каноническое имя победителя
- `names`: дата → название турнира

### 2a. Ручные записи турниров (`manual-tournaments.json`)

Официальная таблица победителей иногда обновляется с задержкой. Чтобы показывать победителя и название турнира, не дожидаясь её, есть «опережающий» источник — файл `manual-tournaments.json` в корне репозитория.

Формат — массив объектов:
```json
[
  { "date": "07.06.2026", "name": "DISCIPLINE TOURNAMENT", "winner": "XR" }
]
```
- `date` — в формате `ДД.ММ.ГГГГ` (как в официальной таблице);
- `name` — название турнира (опционально);
- `winner` — ник победителя (опционально, прогоняется через `resolveName`).

**Приоритет:** официальная таблица **всегда** перекрывает. В `loadNewTableMaps` ручные записи подмешиваются только для того, чего ещё нет в официальной — название и победитель проверяются раздельно (если официальное название уже есть, а победителя ещё нет, подтянется победитель из ручной записи). Как только официальные данные появляются, ручная запись автоматически перестаёт учитываться; её можно удалить из файла.

Файл читается один раз при старте сервера (`readFileSync`), поэтому изменения применяются после деплоя/перезапуска. Пустой файл (`[]`) — обычное состояние, ничего не подмешивает.

### 3. Supabase

Таблицы: `users` (telegram_id, username, first_name = ник, rating), `games` + `registrations` (+вью `games_with_count`) — запись на предстоящие игры.

## Ключевая бизнес-логика

### Нормализация ников (`ALIASES`, `resolveName`)

Один игрок встречается в таблицах под разными написаниями (регистр, перестановка имени/фамилии, точки, пробелы, е/ё, опечатки). `resolveName(raw)` приводит сырое имя к каноническому через словарь `ALIASES` (ключ — lowercase-вариант, значение — каноническое написание).

Сравнение «имя из таблицы ↔ запрошенный ник»: `matchesNick(raw, nickname)` — резолвится **только** сырое имя из таблицы, запрошенный ник сравнивается как есть (lowercase).

**Методология поиска новых дублей** (запускать при жалобах на «потерянную» статистику):
собрать все сырые имена из всех листов и искать пары по критериям: одинаковые слова в разном порядке; совпадение после deep-нормализации (убрать точки/пробелы/апострофы, ё→е, э→е); Левенштейн ≤1 на нормализованных строках. Канон — у кого больше суммарных очков, при равенстве — кто в более свежем листе. **Осторожно:** короткие пары вида «Иван А»/«Иван П» — почти всегда разные люди.

### Подсчёт побед

Победитель дня определяется **только** по новой таблице. Турниры из `WINNER_EXCLUDE` (финалы месяца/сезонов: `FINAL OF THE MONTH`, `ЛЕТНЕГО СЕЗОНА`, `ВЕСЕННЕГО СЕЗОНА`) победами не считаются.

Место игрока в конкретной игре:
- победитель из новой таблицы → место 1;
- лидер по очкам, не являющийся победителем (выигравший получает фиксированные очки не всегда максимальные) → место 2;
- остальные — ранг по очкам за день.

⚠️ Победа учитывается в статистике игрока только если на эту дату у него есть очки в рейтинговом листе. Победа в турнире, отсутствующем в старой таблице, в личной статистике не видна.

### Скрытые игроки

`HIDDEN_PLAYERS` (сейчас: `klu4`) — исключаются из всех публичных выдач (рейтинг, все игроки, легенды, результаты игр, статистика клуба, подсказки ника). Данные в таблицах не трогаются.

### Коррекции дат

`WINNER_DATE_CORRECTIONS` — исправления опечаток в датах новой таблицы (сейчас: 03.02.2026 → 02.02.2026).

### Парсинг дат

`ruDateToISO(label, year)` понимает форматы «27 мая», «4 июн.» (полные и сокращённые русские месяцы из `RU_MONTHS`), «27.05». Год берётся из `SHEET_YEAR` по ключу месяца.

### Кэширование

Все листы кэшируются в памяти на 5 минут (`CACHE_TTL`). Изменения в Google-таблицах подтягиваются автоматически с этой задержкой. Перезапуск сервера сбрасывает кэш.

### Текущий месяц

`CURRENT_MONTH` в server.js — единственное место, задающее месяц по умолчанию для API. На фронтенде продублировано в `public/app.js` (`currentMonth`, `allGamesMonth`, дефолт `openGameResults`) и в `public/index.html` (первые `<option>` обоих селекторов).

**Чек-лист перехода на новый месяц:**
1. Создать лист в старой таблице, узнать его gid (из URL).
2. server.js: добавить месяц в `SHEETS`, `MONTH_NAMES`, `MONTH_ORDER`, `SHEET_YEAR`; обновить `CURRENT_MONTH`.
3. public/app.js: обновить три дефолта.
4. public/index.html: добавить `<option>` первым в оба селектора.

## API

Все ответы — JSON. Ошибки: `{ error: string }` со статусом 400/404/500.

### Рейтинг и статистика (Google Sheets)

| Эндпоинт | Параметры | Описание |
|---|---|---|
| `GET /api/rating` | `month?` | Рейтинг месяца: `[{ first_name, rating, place }]` |
| `GET /api/player-stats` | `nickname`, `month?` | Статистика игрока за месяц с разбивкой по играм: `{ found, gamesPlayed, totalPoints, bestPoints, bestPlace, games: [{ label, idx, pts, place, total, tournamentName }] }` |
| `GET /api/player-overall` | `nickname` | Статистика по всем месяцам: `{ nickname, totalGames, totalPoints, allBestPoints, allBestPlace, totalWins, months: [...] }` |
| `GET /api/my-results/:telegramId` | — | То же, но ник берётся из Supabase по telegram id |
| `GET /api/past-games` | — | Последние 3 игры текущего месяца |
| `GET /api/all-past-games` | `month?` | Все игры месяца (свежие первыми) |
| `GET /api/game-results` | `col`, `month?` | Результаты одной игры; победитель — первым: `{ tournamentName, players: [{ first_name, rating, place }] }` |
| `GET /api/all-players` | — | Сводный список за всё время: `[{ name, totalPoints, months }]` |
| `GET /api/player-tournaments` | `nickname` | Все турниры игрока (новые первыми): `[{ dateISO, label, pts, tournamentName, isWinner, month, colIdx }]` |
| `GET /api/legends` | — | Топ-15 по победам за всё время |
| `GET /api/club-stats` | — | Агрегаты клуба: турниров, игроков, участий, рекорд, чемпион, самый активный |
| `GET /api/club-averages` | — | Среднее очков за игру по клубу для каждого месяца: `{ monthKey: avgPpg }` (сумма очков месяца / число участий). Используется как линия сравнения на графике «Среднее очков за игру» |
| `GET /api/suggest-nickname` | `q` | Для регистрации: `{ exact, canonical?, suggestions: [0..1] }` — точное совпадение через алиасы либо fuzzy-подсказка (Левенштейн ≤2 или подстрока, минимум 4 символа) |

### Игры и профиль (Supabase)

| Эндпоинт | Описание |
|---|---|
| `GET /api/games` | Предстоящие игры с количеством записавшихся |
| `POST /api/games/:id/register` | Запись на игру (body: telegramId, username, firstName); создаёт юзера при первом обращении; проверка дубля и лимита мест |
| `DELETE /api/games/:id/register` | Отмена записи |
| `GET /api/my-registrations/:telegramId` | id игр, на которые записан |
| `GET /api/profile/:telegramId` | `{ first_name, username }` или null |

| `GET /api/profile-stats/:telegramId` | Краткая статистика текущего месяца для профиля: очки, игры, лучший результат, место в рейтинге |

## Фронтенд

Нижняя навигация — 4 вкладки: **Игры** (`tab-games`), **Рейтинг** (`tab-rating`), **Легенды** (`tab-legends`), **Игроки** (`tab-players`).

Дополнительные экраны (открываются поверх): все игры месяца, результаты игры, статистика игрока за месяц, общая статистика игрока, мои результаты, мои турниры, график прогресса (Chart.js: очки+победы по месяцам и средние очки за игру, последние 12 месяцев), статистика клуба, профиль, о клубе, правила, регистрация ника, подсказка ника.

Идентификация: внутри Telegram — `window.Telegram.WebApp` (telegram id), в браузере — ник в `localStorage` (`pride_nickname`).

## Telegram-бот

`/start` — приветствие + inline-кнопка «Открыть клуб» (web_app, url из `APP_URL`); `/help` — список команд. Long polling.

## Разработка и тестирование

Запуск: `npm start` (сервер+бот) или `node server.js` (только API, без бота).

**Регрессионное тестирование** (`snapshot.mjs`): снимает ответы ~35 GET-кейсов всех эндпоинтов в JSON-файл.
```
# до изменений
TEST_PORT=3100 node snapshot.mjs baseline.json
# после изменений (перезапустив сервер)
TEST_PORT=3100 node snapshot.mjs after.json
# сравнить файлы — ответы должны совпадать, кроме намеренных изменений
```

Деплой: автоматический с пуша в `main` (GitHub: erinnikita654-oss/Pride_app).

## Известные ограничения

- CSV-парсер старой таблицы не учитывает запятые внутри кавычек (пока в данных не встречались).
- Победа в турнире, которого нет в рейтинговом листе, не попадает в личную статистику (только в «Легенды» и `club-stats`, которые считают напрямую из новой таблицы).
- Кэш в памяти процесса: при нескольких инстансах сервера у каждого свой.
- `ALIASES` пополняется вручную; новые дубли имён нужно периодически проверять скриптом (см. «Методология поиска новых дублей»).
